# 目标与运行上下文

更新日期：2026-10-06（Asia/Hong_Kong）。

## 当前目标

尽可能提高 Windows NR 效率，不以 160 FPS 或任何特定帧率作为验收承诺。
优先保持现有精度和模型行为；有损方案必须遵循 [decisions.md](decisions.md) 的独立开关要求。

用户确认的目标环境：

- GPU：AMD Radeon RX 9070 XT。
- 用户报告的驱动：26.8.1；2026-10-06 通过 WMI 核验 Windows 驱动为
  `32.0.31041.1004`，驱动日期 `2026-08-17`。未独立核验其与营销版本号的映射。
- 目标输入：2258×1270；独立原生计划已确认为 2368×1280 工作尺寸，游戏侧仍需核对。
- 链路：游戏输入 → 100% 模型分辨率、单次 Mochizuki NR → FSR4 平衡档 → 3840×2160。
- 用户使用外部 `dlss-5-amd-project` 宿主，可能在下游启用 4× XeSS FG。
  核心基准先隔离 FG 和游戏负载，集成验证再分别记录 FG 关闭/开启的表现。

## 已确认的代码关系

调查时本仓库 HEAD 为 `82560c4fbfaac347fc5e22c22025191402ae916b`。
宿主 Mochizuki 的上游 pin 同为该提交，但包含本地适配及着色器生成补丁，不能假定二者构建产物一致。
接入宿主时需重新核对当前 pin、补丁和配套 ABI。

该宿主让游戏保持原生 D3D12，通过共享缓冲区与 Vulkan NR 交换数据并同步。
官方安装路线的 DXVK/vkd3d-proton 整体转译成本不能套用到这条链路。
宿主显示的网络计时不覆盖整帧、D3D12 搬运、SR 和 FG。

## 历史观测，不能用作目标分辨率基线

用户截图：OptiScaler(NR) 1.10.2，Mochizuki 0.0.3，2560×1440 → 3840×2160，
NR → SR、100% 模型分辨率、1 pass；强度 2.00、Cinematic。
网络中位数 14.20 ms、P95 14.42 ms，截图整帧 31.49 ms、SR 1.82 ms。
这是用户提供的历史观测；场景、采样窗口、时钟和完整设置未受控。
这些读数不能直接相减以准确归因剩余成本。

2258×1270 的独立网络基线与两种静态输入对照已建立，见
[EXP-001](experiments/EXP-001-windows-2258-baseline.md)。真实游戏及时间历史基线仍待建立。
不按像素比例宣称实际收益，也不将离线 FP32 输入成绩替代宿主实际格式的成绩。

用户于 2026-10-06 明确要求先继续优化，暂不进入游戏测量；当前优先离线内核实验与宿主本地 GPU 验证。
