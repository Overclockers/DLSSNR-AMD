# EXP-006：Windows C512 FFWD 与投影融合

日期：2026-10-06。结论：**四种融合布局在独立算子对中均更慢，没有保留生产改动。**
这轮验证了完整算子上下文，未将局部输出一致当作整网或游戏验收。

## 假设与范围

目标图有 16 对 `CCSplitSwin16HFfwd` → `CCSplitSwin16HFfwdProj`。
每对当前使用 `ffwd3w` 和 `gemmproj`，有效域为 **3040 tokens × 512 channels**。
融合尝试把中间 FP8 张量留在 LDS，省去一次全局存取和一次 dispatch 边界。
主要代价是八个独立 FFWD 组必须在同一工作组相遇，改变已有的权重缓存复用和并行分工。

基线为主仓 `a6829dd`、宿主 `38ea72c`。生产源、Linux 和宿主均未修改。
原型仅位于忽略的 `build/windows/exp006/`，不是用户可安装功能，没有引入有损模式。

## 输入、环境与数值边界

- RX 9070 XT；程序直接报告 `AMD proprietary driver / 26.8.1 (LLPC)`。
- 使用 2258×1270 RGBA32F 验证照片建立原网络；工作尺寸 2368×1280，800 ViT tokens。
  默认控制、100% 模型尺度、单次 NR、arena reuse，无时间历史、SR、FG、游戏或 D3D12 搬运。
- 分别执行原图前缀，取得第一对 `b23l0→b23l1` 和最后一对 `b47l0→b47l1` 的实际输入和残差。
  数据仅在本地内存/忽略目录内使用；不提交或分发模型、中间张量或输出文件。
- 保留三处 FFWD FP16→FP8 边界、半精度激活、投影 FP32 累加、原残差表达式及输出量化。
  投影继续按 X×Wᵀ 计算，每个输出的 K 顺序仍递增；没有交换乘法方向或归约顺序。
- 四个权重矩阵均沿用原图已经注册并打包的 A、Q0、Q2、projection 偏移和布局。
  研究程序在原图完成打包后创建候选 kernel，没有新增生产 lowering 或改变模型格式。
  若未来正式融合，仍须将全部四个矩阵注册到生产 packing 并同步 manifest。

检查时未发现 `yysls.exe`。未持续采集后台 GPU 负载、频率、温度或缓存性能计数器。
最后一对的两次普通测量与 CPU 编译并行；没有与 GPU 统计采集或其他研究 GPU 进程重叠。

## 四种布局

| 布局 | 每组每 wave 的 tokens | waves / 工作组 | 整个工作组覆盖 tokens | LDS |
| --- | --- | --- | --- | --- |
| `fused16` | 16 | 8 | 16 | 8 KiB |
| `fused32` | 32 | 8 | 32 | 16 KiB |
| `locality16` | 16 | 16 | 32 | 16 KiB |
| `locality32` | 32 | 16 | 64 | 32 KiB |

前两种每 wave 拥有一个 FFWD 组，通过一次工作组 barrier 交换量化后的中间值。
后两种让相邻两 wave 处理同一组的不同 token 范围，以增加组内权重复用。
每个 token 的计算内容不变；LDS 的协作矩阵访问保持 16 字节对齐。
`locality32` 的最后一个工作组有一个无效 token 单元，守卫保证它仍参与 barrier，随后不投影或写输出。

## 构建与隔离

MSVC 14.51.36231，C++17 `/O2 /MT`；glslang 16.5.0，Vulkan 1.3。
采用宿主现有 quad conversion 和循环展开流程。首先独立重编译原来的两个算子，
与保存的宿主 SPIR-V 逐字节一致；这些算子继续作为对照。

研究程序给输入、残差、中间值和最终输出分配互不重叠的区域，并设置尾部 guard。
所有方案使用同一设备、相同资源、相同输入及相同输出地址。
`control` 重复运行原来的两个算子，用作同配置空对照。
每次正确性检查前重新写入输入并污染输出，避免候选漏写却读到前一方案的正确值。

## 测量方法与结果

每次普通调用先运行原网络 100 帧，再给四种测量配置各预热 256 对。
各配置测 **12 批 × 256 对**；相邻两轮反转顺序，并轮换起点。
每次提交最多执行 16 对短算子，保留依赖 barrier；没有逐层 timestamp。
GPU 时间覆盖整对算子，单位 ms；它不是 NR 帧时间。

| 工作组布局 / 输入层 | 原算子对 | 同配置空对照 | 16-token 候选 | 32-token 候选 |
| --- | --- | --- | --- | --- |
| 8 waves / 第一对 | 0.059510 | 0.059722 | 0.067591 | 0.071223 |
| 8 waves / 最后一对 | 0.061003 | 0.060840 | 0.068219 | 0.070970 |
| 16 waves / 第一对 | 0.059323 | 0.059486 | 0.076696 | 0.070060 |
| 16 waves / 最后一对 | 0.060903 | 0.060675 | 0.079191 | 0.070032 |

四种候选在所测两层的每一批都更慢；相对各自调用内基线，退化约 **11.83%～30.03%**。
空对照均值差约 -0.000228～+0.000212 ms，不能将它视为通用误差界限。
批次内绝对耗时有明显漂移，CSV 保留了完整顺序；结论依赖交错对照，未跨会话相减或外推整网损失。

共 **6 次 GPU 研究程序调用**：4 次普通性能调用，测 **49,152 对**；2 次驱动统计调用，
各配置仅取 1 个附带计时，合计 8 对，**不纳入性能结论**。
另有 402 个原网络预热帧、6 次前缀执行、6,144 对算子预热和 24 次正确性执行。

## 驱动代码与原因边界

| shader / 布局 | VGPR | LDS 字节 | scratch 字节 |
| --- | --- | --- | --- |
| 原 `ffwd3w` | 182 | 0 | 0 |
| 原 `gemmproj` | 75 | 0 | 0 |
| `fused16` | 84 | 8192 | 0 |
| `fused32` | 181 | 16384 | 0 |
| `locality16` | 102 | 16384 | 0 |
| `locality32` | 174 | 32768 | 0 |

没有观察到 scratch 溢出；LDS 生成了成对 64-bit 读取，不是逐字节读。
因此不能把退化简单归因于溢出或错误的 LDS 对齐。
融合改变了原有 group-major 权重共享，并增加 LDS/barrier 成本；恢复部分共享也没有反转结果。
这些是结构和 ISA 支持的解释方向，没有硬件计数器证据把耗时精确归因给其中某一项。
结论只排除已测四种布局，不证明所有融合设计都不可行。
