# EXP-050：当前分支与指定上游的四分辨率直接对照

日期：2026-10-07（Asia/Hong_Kong）。本项是用户要求的组合效果验证，不是新的优化假设。

## 比较身份与范围

- 基线：`82560c4fbfaac347fc5e22c22025191402ae916b`，使用本地已有 Git 对象。
- 当前：`main` 的 `b861a6fdcb2005ecfea8271548f5de24f5fa4b19`。测量开始时无已跟踪文件修改。
- 两端各自从 Git 导出完整 Windows 源快照，独立编译核心和匹配 shaders，保留各自 arch defines、pipelines.json、原生计划器和模型打包方式。没有套用宿主 fork 的 shader 补丁。
- 同一私有用户模型、glslang 16.5.0、MSVC x64 /O2 /MT /std:c++17；为旧源码提供已有的 Windows dirent.h 空实现兼容头，仅禁用不可用的 Linux sysfs 遍历，不改网络实现。
- 通用 Vulkan 调用夹具两端相同；当前端按新增 API 创建并持有 LinearInputBinding、声明实际启用的 storage-image-extended-formats，使默认直接 packed/融合输入路线可用。旧端走该提交原有线性输入路径。
- 不是 Mochizuki 宿主 DLL 的 A/B。EXP-001 的 C256 edge bodies 在指定上游配方已启用，不能把该历史宿主收益额外加到本结果。

## 环境与测量口径

GPU 为 AMD Radeon RX 9070 XT，Vulkan 实测驱动 `AMD proprietary driver / 26.8.1 (LLPC)`。
输入为既有验证照片的 2258×1270 FP32 副本，按 nearest 缩放至各分辨率后量化为 R11G11B10；两端使用完全相同字节。
线性输入、white point 1、100% 模型尺寸、单 pass，RuntimeConfig/Controls 其余为两提交共同默认值；无 temporal、mask、preprocess、SR 或 FG。
每帧先在 GPU 上从独立原图恢复输入；恢复复制及其依赖完成后开始 timestamp，随后调用 Runtime::record，并在完整执行结束写 timestamp。
计时包含核心内部输入准备/编码、网络、合成和回写，不包含夹具输入恢复、CPU 录制/提交、初始化、驱动编译、读回、D3D12 搬运、跨 API 同步或游戏整帧。
单帧提交并等待完成，只有一个帧在途；不同于先前宿主 depth=3 的完整 D3D12→Vulkan→D3D12 测量，不混减两类绝对时间。
保留核心原有计时，另加相同的外部 timestamp 对；无逐层 timestamp。没有修改频率或驱动，未锁频，未采样温度、时钟及持续后台负载。

每个分辨率：ABBA×3，再 BAAB×3；每批预热 100 帧、测量 200 帧，A/B 各 2400 帧。
随后当前版本 CCCC×2，以外侧两批对内侧两批估计同路径控制差，共 1600 帧。
四分辨率合计 128 个正式批次、25,600 个测量帧、12,800 个预热帧；另有 8 次短 smoke，各预热/测量 3 帧，不纳入性能统计。
进程串行执行，清除继承的 NR_* 研究覆盖项（本次实际为空）；使用各端已建立的 pipeline cache。所有正式批次均保留，没有剔除慢帧或选择最快批次。

## 复现与结论

私有夹具和完整证据位置记于 `.ai/local/upstream-resolution-comparison-20261007.md`；模型、可执行文件、源快照、缓存及回读留在忽略的 build 目录。

```text
runtime_bench.exe <matched-assets-root> <width> <height> 100 200 <batch.csv> <output.raw> <2258x1270-photo.rgba>
python -X utf8 measure.py
python -X utf8 summarize.py
python -X utf8 verify.py
```

每个 assets root 使用该提交自己的 dlssnr-amd/shaders 和同一个用户模型。夹具通过各自 rdna4.sh 定义编译 nr_runtime.cpp 与 nr_native_plan.cpp；prepare.py 保存完整构建命令和身份。
复现时使用新的输出目录，避免覆盖本次证据；smoke 只验证启动与输出，正式测量按上面的固定顺序运行。

本次直接对照确认当前组合在四个测量尺寸下均有收益；1080p 收益约 0.49%，目标尺寸和 1440p 约 3.1%，4K 约 3.48%。
六组 A/B 的最小收益分别高于各尺寸观测到的控制最大绝对组差。
优化具有分辨率依赖：例如小 ViT 收缩只选择 768–1024 tokens 的变体，800/960 命中，640/2160 不命中。本次没有逐项消融，不能从汇总结果确定各项优化的贡献，4K 的收益也不能归因于该小 ViT 变体。
不把旧会话的增量相加，不外推游戏 FPS、FSR4/FG 或其它 GPU/驱动。生产源码、宿主、Linux 均未修改；按用户要求提交验证文档，没有部署、安装、打包或推送。
