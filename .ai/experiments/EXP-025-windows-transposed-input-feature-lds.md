## 假设与实现

EXP-024 的成对存储减少了指令，但保留 token 间 32 字节的写入步长。本假设改变 LDS 地址分布。静态条件模型在 32/64 个四字节 bank 假设下，原布局每 bank 分别最多 8/4 个 lane，转置后为 2；这不是硬件冲突计数或实际事务证明。

版本 1：同样的 64×16 个 half，从 `[token][feature]` 转置为 `[feature][token]`，cooperative B load 改为 RowMajor、stride=64 half。1024 元素一一映射；byte stride=128，片段 byte offset=0/32/64/96，均满足 16-byte 对齐。

版本 2：保留原方向，每 token 填充为 24 个 half；load stride=48 字节、片段 byte offset=0/768/1536/2304。CPU 对照确认读写集合均为相同 1024 个 live 元素，512 个 padding half 不会被读。每个特征的原 scalar half 转换、WMMA 输入顺序和 barrier 均保持。第二版针对第一版读取变窄这一实际 ISA 结果，未改变数学。

两版 VGPR 都为 124、scratch 为 0。转置保留 LDS 6144 字节，但输入片段读取从两条 `ds_load_b128` 变为 16 条 half load；pre 诊断 0.893→0.897 ms。填充恢复两条 b128 load，LDS 增至 7168 字节；pre 诊断 0.895→0.909 ms。没有硬件计数器，不能把差值精确归因于 bank 冲突或驻留数量。
