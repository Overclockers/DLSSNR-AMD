# EXP-004：Windows 转换链与融合舍入边界

日期：2026-10-06。结论：五组候选均未保留；没有新的可靠性能收益。
保留了一组可复现的精度反例：转换函数对已存储输入等价，不代表它接在乘加后仍与原内核等价。

  输入仍是 EXP-001 的重采样验证照片；默认控制、无时间历史、无游戏/SR/FG/D3D12 搬运。

## 假设与筛选

只探索保持默认算术行为的候选；结果改变的方案直接排除，没有作为可选有损功能交付。
修改均在忽略目录的源码副本中，涉及 `include/coopmm.glsl` 与 `include/swin_math.glsl`。

| 候选 | 具体机制 | 目标照片结果 | 性能/处置 |
| --- | --- | --- | --- |
| `half-range1` | 已是半精度的量化输入先在半精度做 clamp 和非有限值传播，再转 FP8 | 字节一致 | pre 反而多出 32 条半→单精度转换；无保留价值 |
| `half-range2` | 半精度 clamp 后扩展到 FP32，再执行原来的非有限值传播 | 字节一致 | 与上一项类似，未见明确收益 |
| `exp-clamp` | 指数转换先在 FP32 clamp，再窄化到半精度 | 输出改变 | 破坏融合舍入；C32 普通层约 1.226 → 1.253 ms，排除 |
| `exp-round` | 在有界区间以 FP32 加 8192 实现半精度格点舍入，再构造结果位模式 | 输出改变 | 同样破坏融合舍入；C32 普通层约 1.226 → 1.270 ms，排除 |
| `exp-packed` | 保留融合乘加，在半精度上下界之间插入有界等价的位操作，促使生成成对 min/max | 字节一致 | 最终四对整网无收益，排除 |

以上内核数字来自早期逐层筛选，只用来筛除方案，不能视为最终整网收益。
`half-range1/2` 对普通 `fswin32` 没有有效改动：该内核的相关路径已经使用 FP32 量化入口，SPIR-V 未变。

## 数值探针：独立输入通过，乘加输入失败

第一组对照独立编译并分开 dispatch 基线/候选：

- 半精度量化：全部 **65,536** 个半精度编码，包括两种零、subnormal、Inf 和 NaN；两种改写完全一致。
- 指数转换：**8,653,828** 个 FP32 输入，包括 `[1, 2)` 内全部 8,388,608 个编码，
  符号/指数分层样本、特殊值及确定性随机位模式。原算法的有效 clamp 区间完全包含在其中；
  两种 FP32 改写对这些已存储输入完全一致。

但原 `nr_swin_exp_baked` 的输入不是独立存储的值，而是
`f16vec2(fma(x, vec2(0.044921875), bias))`。本机 LLPC 将乘加与窄化一起降为
`v_fma_mixlo_f16` / `v_fma_mixhi_f16`。把 clamp 移到窄化前或改用 FP32 舍入构造，
会让乘加结果先舍入到 FP32、再舍入到半精度，边界行为随之改变。

第二组探针加入这个上游乘加，使用 **1,048,576** 组确定性有限 `x/bias` 输入。
`exp-clamp` 和 `exp-round` 各出现相同的 **38** 个差异。
用 Python `Fraction` 对全部 38 个反例计算精确乘加值，GPU 基线均符合直接半精度舍入，
候选均符合先 FP32、再半精度的两次舍入。

一个可复现反例：`x` 的 FP32 位模式为 `0xbd9b9e41`，`bias` 为 `0x3fa9bfda`，
乘数为精确的 `46/1024`。指数转换最终输出的半精度编码：基线 `0x2960`，两次舍入为 `0x2940`。
该问题不是放大精度就自动等价；默认路径要求保持已有输出和舍入边界。

完整网络中，`exp-clamp` / `exp-round` 相对照片基线分别改变 8,602,305 / 8,602,307 个 FP32 分量，
最大绝对误差约 0.0490 / 0.0610。它们不是可忽略的文件哈希差异，也未进行画质可接受性评估。

## 保留融合的最后一次尝试

`exp-packed` 保持 `f16vec2(fma(...))`，然后执行半精度 max、位操作、半精度 min：

```glsl
const f16vec2 lower = max(f16vec2(fma(x, vec2(0.044921875), bias)), f16vec2(1.03125hf));
const f16vec2 positive = unpackFloat2x16(packFloat2x16(lower) | 0x3C003C00u);
const uint h = packFloat2x16(min(positive, f16vec2(1.5693359375hf)));
return unpackFloat2x16((h << 5u) + 0x7FF88000u);
```

位操作在有效区间内是恒等变换；对上界之外的正值，它可能生成更大的正数、Inf 或 NaN。
本机 `min_num` 对生成的 NaN 选择有限上界，因此最终 clamp 结果仍一致；这依赖实测的驱动语义，
不能仅以位模式的数值次序证明跨驱动等价。
它通过了前述 8,653,828 个独立输入、1,048,576 组乘加输入以及目标照片整网对照。
驱动确实生成了成对的 half min/max，并保留融合乘加，但没有降低实际整网耗时。

| C32 普通内核 | VGPR | LDS 字节 | 静态指令行 | 解释 |
| --- | --- | --- | --- | --- |
| 基线 | 189 | 2048 | 4867 | 对照 |
| `exp-clamp` | 189 | 2048 | 5032 | 融合乘加被拆开，另付窄化成本 |
| `exp-round` | 188 | 2048 | 5114 | 省去部分窄化，但位构造/调度开销增加 |
| `exp-packed` | 189 | 2048 | 4898 | 64 次打包与 128 次 scalar half clamp 被替换，但出现位操作与额外调度 |

上述内核 scratch 均为零。静态计数包含 buffer/LDS 指令，每个 VOPD 指令行计一次；
它不是动态执行次数或吞吐量预测。`exp-packed` 的 min/max 各 64 条，FP8 MODE 写入仍为 193 条。

仅对保持输出一致的 `exp-packed` 做四对 A/B、B/A 交替测试。

## 后续条件

转换探针必须带上实际的上游生产运算，必要时带下游消费者；独立输入穷举不能替代上下文中的舍入验证。
不要重新启用这五个候选，也不要继续扫描 EXP-001..003 已否定的 wave/LDS 参数。
下一轮可先检查计划中的 dispatch、同步和中间张量搬运是否存在可消除的开销；
微小内核收益则应采用更紧密的交错测量，减少跨进程热状态漂移，再谈保留与宿主整合。
