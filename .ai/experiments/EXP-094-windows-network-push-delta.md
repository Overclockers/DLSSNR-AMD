## 假设与实现

网络每次 dispatch 原本都更新整个 push block。原型只在一次网络 pass 的局部缓存中比较相邻数据，Kernel.create 保存实际单个 COMPUTE、offset=0 的范围；范围相同且完整写入时，按4字节裁掉相同的前后缀，只提交剩下的连续范围。空、部分、超过256字节或不符合对齐的块执行原调用并清空缓存；每个 pass/recording 重新初始化。pipeline、descriptor、dispatch、barrier 和全部shader不变。不同于 EXP-041 的录制重放或 EXP-064 的绑定复用。依据 [Vulkan 增量更新及布局兼容规则](https://docs.vulkan.org/spec/latest/chapters/descriptorsets.html#descriptorsets-push-constants)，只复用相同 push ranges 已写入的数据。

用实际 C++ PushCache 配合模拟 Vulkan 写入执行1,000,000次随机/布局切换/部分块/空块检查、4000次重置，全部字节与范围来源标签匹配原版；包括16–320字节范围，probe SHA256 `16f495fba3d9d49a8629767c9e8ea17becddba81be6cef6d6478e09b93642ee1`。实际目标7次录制均保持123次调用，数据8652→8128字节，减少524字节；route证据 SHA256 `181ff87915f291cf550eb26319154816bd99856b70828e97c1b9188775f250b7`。初始构建清单没有记录历史obj哈希，故两臂都从固定源码重编全部4个对象，没有直接信任旧obj。关闭宏后的 DLL .text与继承生产基线完全相同：749260字节、SHA256 `b866ecbd485e40dbe5d27f92b3ecbe837ed990681ba6ab3cfa50a839c868d802`；候选 .text749900字节。单独原版源码构建作A臂，所有完整宿主packed输出相同。未运行不能覆盖Runtime录制修改的standalone。ADL只读采样含初始化/预热；没有把CPU录制成本推断为GPU收益。
