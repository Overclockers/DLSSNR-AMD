## 分段工具与测量口径

可复现入口：[profile_host.py](../../windows/build/profile_host.py)；
操作及字段定义见 [Windows host profiling](../../docs/windows-host-profiling.md)。
工具只读宿主，在本仓库 `build/` 内生成 DLL、计时程序及验证程序，不复制模型。
诊断宏在普通构建中关闭；不修改游戏菜单，也不改变现有 UI 计时含义。

查询按提交编号和槽位关联。先证明 D3D12 consumer tail 和相应 Vulkan fence 完成，
再取查询并回收；支持三帧在途及逐帧 CPU 等待。完整计时与分段插桩分别采集。
跨 API 只比较各自换算后的时间**区间**，没有直接相减原始时钟。
交接残差包含 CPU 提交空隙与两个方向的交接，不能进一步归因为某个方向的 GPU 等待。

最终分段诊断为 12 批×120 帧，A/B/B/A×3，预热 100 帧；下面是原路径均值的近似值：

| 部分 | ms | 含义 |
| --- | ---: | --- |
| 网络算子循环 | 10.580 | 约占此诊断完整 NR GPU 区间的 94% |
| 输入转换＋编码 | 0.091 | 本轮优化范围 |
| 输出合成＋核心回写 | 0.369 | 含 alpha 和输出格式处理，未在本轮优化 |
| 两侧 D3D12 与外层 Vulkan 搬运 | 0.095 | 四个复制区间之和 |
| 交接残差 | 0.145 | 含提交空隙，不是纯驱动或单向等待 |
| 完整 NR GPU 区间 | 11.286 | D3D12 输入开始到 D3D12 输出结束，另有少量内部准备区间 |

搬运不是这组离线负载的主瓶颈。CPU 录制与 GPU 执行可重叠，不能相加当帧时间。
初始 1/3 帧在途各做两轮普通及两轮分段测量；串行等待增加区间之间的空隙，
因此最终性能采用三帧在途。不同批次的绝对毫秒数不交叉相减。

## 实现与筛选

第一候选保持独立的原格式中转图，再由 encode 采样：转换约 0.022→0.014 ms，
但编码约 0.069→0.078 ms；12 轮交错普通测量没有稳定收益，**未保留**。

保留版本由 encode 直接采样宿主已上传的颜色图，同时写出原有 FP32 proxy 和 keep。
`runtime_encode_sampled.spv` 由原 encode 源加一个采样入口定义生成，后续色彩运算完全共用。
只启用于线性 R11G11B10/RGBA16F、100% 尺度、单遍容量、未配置预处理/外部 mask 的情形。
没有合适 binding 或其它配置继续走原路径；绑定创建失败也回退。

新 `LinearInputBinding` 与源 allocation、network 的身份相符才可用。
宿主录制对象拥有 binding，释放遵循现有 consumer tail；弱缓存不延长旧网络/图像的寿命，
也不按裸 VkImage 数值缓存。重放、旧尺寸录制和执行时参数仍由原录制 ABI 管理。
没有以帧数代替完成证明，也没有修改在途 descriptor。

## 最终性能

同一个诊断 DLL、同一网络/资源，关闭额外分段时间戳，运行 A/B/B/A×6，
24 批×200 帧、100 帧预热；两个路径各 2,400 测量帧。

| 完整 NR GPU 区间 | 原路径 | 直接编码 | 节省 |
| --- | ---: | ---: | ---: |
| 4,800 帧均值 | 11.209948 ms | 11.194527 ms | **0.015421 ms / 0.138%** |

六组 A/B/B/A 平均节省分别为：
`0.008891 / 0.016476 / 0.021854 / 0.015474 / 0.009190 / 0.020644 ms`。
另一次 12 批同路径空对照平均差为 `-0.001808 ms`，三组为
`-0.010802 / +0.006384 / -0.001007 ms`。这只是本次控制测量，不是通用误差界限。

独立分段批次中，输入转换＋编码由 `0.091136` 降至 `0.066286 ms`，约少 27%；
该批完整区间节省约 `0.013957 ms`。不能把 27% 说成整网或游戏提速。
保留的是小成本优化，不改变“下一步主要收益仍需从网络算子寻找”的判断。
